# Testing and native probes

Use JDK 21 and the checked-in wrapper:

```sh
./gradlew --no-daemon check build probeJar clientProbeJar
```

Probe JARs are separate from the released mod. Use disposable instances and exact artifact/configuration digests; a successful build is not native verification. [Verification](verification.md) owns retained results and their limits.

## Boundary evidence

Separate a codec roundtrip, direct handler call, queued mutation and actual TCP dispatch. For a packet control, record the sender's real game mode/permissions, current menu and dimension, and whether the target lookup creates or loads a chunk. Recheck authority after enqueue at the mutation point. A native fake or embedded player is useful for controlled behavior but does not prove a remote transport path. Preserve an ordinary positive action alongside malformed or unauthorized controls.

Inventory and recovery checks count every native custody owner, including carried records, physical block entities, graves, player inventories and drops. Verify actual death/drop/clone ordering and physical placement, not only a planned recovery record. A successful in-memory count requires normal stop and second-JVM readback before it becomes a saved-state claim.

At a coordinate-frame boundary, observe both delivery and the actual native consumer's outcome. A pipeline recorder that cancels or replaces the force can count calls and inputs; it cannot establish resulting world velocity. Use an asymmetric real body, rotated/tilted controls and the original native pipeline for that claim. Restore temporary observers before the next uncontrolled tick and keep optional activation/fallback qualification distinct from a direct consumer control.

For variable-length decoding or persistence, start with the actual writer and supported producer data. Check complete input, integer arithmetic, cumulative allocation, ownership and publication before choosing caps. Wire and disk formats may differ even when they describe the same object. Include valid nonempty data, truncation, failed publication, concurrent requests and restart; an exception or empty decode alone is insufficient. Retain fatal diagnostics and failed-control receipts outside disposable runtimes, then remove only marked task-owned files.

## Wayfinder

`tools/probe.py --wayfinder --minimal --seed 42 --server /path/to/server/game --java /path/to/java` uses only Compat and its probe with Minecraft/NeoForge. It exercises native command teleports, shapes, hazards, permission and token checks, nearer obstruction and cancellation of an actual cold destination request. It inspects owned tickets and waits for abandoned native work to drain. The endpoints are embedded native players, not remote network clients.

Add `--wayfinder-dh` and omit `--minimal` for the selected full integration set. The fixture imports real native chunks through DH's public lighting/import path, reads their actual columns at several distances and checks cancellation recovery. A malformed-row control reproduces the native getter’s destructive repair, then verifies that Wayfinder’s stored-data read fails without changing the same row. Column readback does not establish a client ray or teleport. Add `--wayfinder-high` for the real Skyweave build-height contract, or use `--wayfinder-public --minimal` for explicit non-operator access.

The existing owned `ClientMiscProbe` supports `skyweave_compat.probe.wayfinder=true`. Its `wayfinder` controls prepare explicit native terrain, aim using Minecraft's actual view vector, inspect the marker, import existing native marker data, and observe the real protocol and destination leases. Prepared test chunks and imports belong to the fixture, never product preview. `reuse` preserves prepared terrain; readiness checks the start and actual target marker, while the real Wayfinder query must observe the intervening data. Preserve artifact provenance with each run and use physical input for activation, rebinding and GUI/held-key checks. For actual TCP qualification, `tools/startup_probe.py --scenario standalone --serve` keeps an owned loopback server alive and forwards console input until `stop`. Set `skyweave_compat.probe.misc.server=127.0.0.1:PORT` on the owned client to connect and reconnect to it. `--without-compat` qualifies the absent-server channel. These modes never bind a public address or reuse the installed server save. A full served fixture can stage authored configuration with `--configuration-pack`; web listeners/downloads are disabled, background DH generation is disabled unless existing-data replay is selected, and the unrelated ADQ periodic interval is deferred to 1440 minutes. These overrides do not qualify those operations. `--replay-dh` accepts a stable cache copy for native server-to-client transfer. That mode uses native CHUNKS_ONLY/PRE_EXISTING_ONLY with a 64-chunk request radius: DH’s disabled plan would also suppress ordinary retrieval. No new terrain or pregen is authorized. Enable the same existing-only plan on the disposable client: DH constrains the negotiated plan to DISABLED if either endpoint disables it, which also prevents ordinary LOD retrieval. `--replay-regions` accepts a marked, seed/digest-bound snapshot of at most sixteen region files, staged only after the new generator establishes its own identity and refusing any region already created by the fixture. No level metadata, source identity or player state is imported. This is saved-data replay, not fresh-generation equivalence. The marked configuration observer can connect to loopback and invoke guarded `wayfinder` column controls; record the actual protocol and landing separately from column readback. For a coarse-only TCP input, start the disposable client with automatic generation and synchronization disabled, pause its renderer, and use the marked observer’s bounded native cache-sync transfer. Sparse stored parents can be synchronized even when DH’s generation-request queue returns `REQUIRES_SPLITTING`; do not pretend those request types are equivalent. Native child proxies must remain intact and must not be credited as genuine fine observations. Reset only an entire stopped, marked fixture cache when a fresh cache is required. `--heap` selects 4G, 6G or 8G for the owned server, with 4G as the default; name the actual heap in its evidence.

## Shutdown under DH load

```sh
python3 tools/probe.py --dh-pregen --dh-stop-after 2 --seed 42 \
  --server /path/to/server/game --java /path/to/java
```

The input server is read-only. The fixture uses a temporary save and random local port, requests a bounded DH job and asks its owned server to stop while the job is active. A normal process exit is required within 90 seconds. Add `--dh-world-key` to exercise UUID cache naming; without it the fixture requires ordinary keys and no new identity marker. These commands never submit work to the input server.

`check` runs geometry tests and verifies upstream artifact hashes. Tests cover void, fragments, exact distance boundaries, narrow unaligned overlaps, full footprints, invalid ranges, negative/world-border coordinates and concurrent calls. To test with an installed server's exact mod selection and config:

```sh
./gradlew --no-daemon check build probeJar
python3 tools/probe.py --server /path/to/server/game --java /path/to/java
python3 tools/probe.py --natural --seed 1 --server /path/to/server/game --java /path/to/java
```

Use `--generation-config /path/to/skyweave_compat-generation.json` to stage an authored candidate profile instead of the installed one. Strict profile parsing rejects obsolete fields; do not accidentally test against an older installed JSON. `--interior-config /path/to/skyweave_compat-interiors.json` similarly stages an explicit cavity/carver comparison without changing the installed instance.

The runner reads installed libraries, mods, config and existing EULA acceptance. It creates a disposable world, binds loopback on an ephemeral port, and removes the temporary server on exit. It never mounts a live save. The probe waits for the first completed server tick, after all startup spawn handlers. Its JAR is separate from release artifacts. Results go to `build/verification`.

`--dh-pregen --seed N --heap 6G` runs the installed DH dedicated pregeneration manager in a disposable full-installation world. It uses the command's minimum 32-chunk radius, waits on that isolated job's future, records region-header entries before/after, and removes the test world. This mode cannot run with `--minimal`. It is a development probe, not a monitor for an operator's server or pregen task.

`--islands --seed N --heap 6G` samples three anchors using 49 spatial strata each. It records observed blocks, weighted estimates, relative ore depths, spawn collision checks, surface biomes, descriptors and generation/scanning time. Reports are JSON and can be consumed by external analysis tools. See [terrain](terrain.md) for sampling limits.

The default heap is 4 GiB; `--heap` accepts 4G, 6G or 8G. The report records the selected limit and observed end-of-scan heap usage. The runner rejects fatal runtime and shutdown errors even when Minecraft exits zero after writing a report. End-of-scan usage is not peak memory or a recommended production allocation.

`--mechanics` calls the installed balloon search and assembly/disassembly helpers at boundary heights. It allows normal ticks for deferred physics cleanup before stopping. Use a separate interactive aircraft fixture for flight and persistence.

`--chunk-futures --seed 42 --heap 6G` compares background FULL requests, explicit retained-ticket controls and the production delivery adapter. The last case invokes ADQ's applied rejection handler and checks that the lease is released. This diagnoses endpoint loading; it does not transport or complete cargo.

### Client probes

`./gradlew clientProbeJar` builds `build/probe/skyweave-client-probe.jar`. Install it only in a disposable client, with desktop authorization before launch. It is excluded from production artifacts and the server probe.

`tools/probe.py --world-output /new/fixture/path` retains a successful, stopped probe world for client inspection. The destination must not exist. Use the same dependencies and generation configuration in the isolated client; this does not export a distributable world or update a personal instance.

For resource comparisons in a full rendering client with Iris, use `-Dskyweave_compat.probe.resources=true`. This mode requires `resource-review-fixture.json` in the disposable game directory and returns before the flight telemetry modes. The owning fixture supplies its world and resources; the probe neither creates a survival world nor installs candidate packs.

`resource-review-control.json` accepts sequenced resource selection, integrated-world commands, native block interaction, container closing, shader switching and shutdown. `resource-review-state.json` records the selected packs, camera, screen, container slots and advancing ticks. Native inspection also records face visibility and world-aware CT quad UVs; raw three-argument model quads are insufficient for this. Iris is optional for resource checks; shader switching requires it. Select one `review-*.zip` treatment above the captured baseline; returning to baseline removes review treatments. Remove stale control files before another launch. Shutdown explicitly halts the integrated server. These controls are test instrumentation, not a production authoring interface.

For SSRD/Sable/Iris/DH distance investigations, also set `-Dskyweave_compat.probe.distance=true`. The marked integrated resource fixture accepts the `distance` operation: `capture: true` records the next opaque construct and LOD draw; a later request reads the observations. `chunks` changes the isolated SSRD client request and sends its native server packet. `dh` toggles the disposable DH renderer. These controls are not production repairs. `nestedFailure` checks the production draw scope's cleanup using one caught, probe-only nested exception. Server ship snapshots run on the server thread and include physics validity and velocities. Resource `command` acknowledgement means queued execution; confirm coordinates, bounds or a subsequent server-thread snapshot before accepting a capture. The marked resource fixture can `rejoin` in-process without the optional world-text fixture. Keep the native terrain distance, shader presets, paused physics, camera and static/assembled controls recorded with captures. Inspect both unobstructed and occluded views; seeing a distant ship alone does not establish depth correctness.
