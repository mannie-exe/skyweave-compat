# Configuration interface

[Operator configuration](../configuration.md#configuration-interface) owns filenames, controls and application timing. This guide owns the consumer bindings, validation boundaries and dependency-update checks.

## Contexts and navigation

`ClientConfiguration` registers one native Configure entry. `ClientSettingsMenus` offers Local files and the running singleplayer server. The native chooser names these contexts; each opens a separate re:form `ClientEditingWorkflow`. Local preferences and next-server defaults never inherit server authority. Remote administration retains native operator commands and requires no client forms protocol.

The 0.4 migration declares separate stable workspace identities and context-specific Home pages. Home links follow the existing category order and admit no settings owner until selected. The workspace title remains the mod name; its subtitle identifies local files or the running singleplayer server. Returning Home preserves open drafts. re:form owns the responsive header, navigation, inspection, review, and document-action bodies; these changes add no persistence or server authority. The minimum local-file workflow has [two-boot native qualification](verification.md#configuration-migration-04-engineering); running-server and current-pack qualification remain separate gates.

`SettingsCatalog` owns concern → mod → purpose organization and stable routes. `ClientSettingsMenus` contributes typed categories, descriptions, placements, timing and actions. A document has one real binding and one retained editor in a workflow. Multiple placements focus the same draft; Iris world text and Island Sky preferences retain their original field IDs in one native rendering document. Navigation aliases and range presentation IDs use lowercase identities independently of camel-case configuration keys. Unavailable optional owners remain attributed destinations without opening foreign classes or inventing an editing baseline.

re:form owns forms, search, filters, focus, native text interaction, retained navigation, review and conflict workflows. Compat contributes labels and relations through `SettingsPresentation`, using existing translations, schema metadata and native spec comments. Field availability explains inactive hooks. Cloud-mode dependencies retain inactive values; changing their visibility does not mutate the document. Numeric units, exact input, bounded probability sliders, collections and native keybindings use shared controls. Do not introduce another widget draft or save path for an auxiliary view.

The entry chooser uses re:form’s `ClientChoiceScreen`, with owner-supplied choices and cached unavailable reasons. The library owns measurement and containment; Compat rechecks actual singleplayer/operator admission before entering a running policy. Do not reintroduce fixed button coordinates or a second permission owner.

`ClientWorkflowLayout.Section` frames the actual composed fields with their purpose and mod caption. Whole-document boxes retain the document title, with the mod and purpose in their eyebrow. It is independent of the navigation category and the underlying document. Fixes on different mod pages still edit the same startup document; Iris and Island Sky projections still share the native rendering owner. Section identities must not become new storage routes, permission contexts, or persistence lanes.

`SettingsLayout` derives related rows from existing `SettingSpec.group` metadata, qualified by the field's parent. It declares bounded sibling rows and labelled boxes through re:form's `FormLayout`; measurement, wrapping, stacking, hit testing, and focus stay in the library. Genuine ordered ranges retain `SettingsCatalog.ranges` and do not receive duplicate related rows. A group of four variant weights uses two related pairs, without adding an ordering constraint. Native category paths supply boxes only: a shared category is insufficient evidence for paired fields. Keep collections in their shared collection editor. Test these declarations against both expanded-map definitions and the exact typed terrain definitions before changing group metadata.

Field purpose appears once, through the field catalog; individual placements do not repeat it above the same control. Uniform local JSON timing and inactive-adaptation context appear once beside that document. Mixed timing, native restart requirements, and field-specific notices use explicit supplemental catalog help, so a translated purpose cannot erase owner facts. Running-server forms use live-owner presentation rather than next-server-default timing. Preserve these distinctions when adding aliases or resource-pack translations.

**Document actions…** opens a shared body inside the retained workspace for the current whole document, including fields outside the selected section. Its actions reuse the retained editor and source guard. Preserve that scope when declaring restore-loaded, defaults, reload, import, undo, and redo labels; a section box does not make these operations section-local. An action returns to its retained owner or the action's guarded review/confirmation body. Standalone and genuinely foreign owners retain their explicit auxiliary hosts.

Shared game APIs use `design.inherent.reform.minecraft`; actual NeoForge registration and native configuration adapters remain in `design.inherent.reform.neoforge`. `AdaptationInformation` contributes the field's purpose, running selection, loaded and draft choices, last observed next-launch choice, fallback, dependencies and related settings. The workspace retains the same draft while its information panel or technical disclosure is open. Omitted keys, explicit false and unavailable dependencies remain distinct observations.

`SettingsFiles` contributes explicit read-only status and OS-open actions for declared local files. The folder action opens Compat's `config/skyweave` directory; individual delegated files retain their actual native locations. Missing paths refuse without creating them. An OS-open receipt reports that a request was submitted, not that an external application displayed the file. Rendering never reads these files; inspection does not save, reload or apply settings.

Owned JSON definitions remain available for staged future-launch editing while their adaptation is inactive. This does not admit foreign codecs or native registrations. Each field retains its declared save/application timing; disabling an adaptation and making a sub-option inactive remain distinct observations. Generation and shape defaults still require their complete paired review.

`SettingsCatalog.dependencies` declares inspected JSON availability, and `ranges` contributes genuine paired endpoints. Inactive fields retain their values and full owner validation. Ocean variant weights and spire controls are not blanket-disabled with ocean edge treatments because native consumers use them independently. Numeric display declares stored probability versus percent and nominal 20-tick seconds explicitly; it preserves exact stored numbers and does not promise wall-clock durations.

`ReformDocuments.scalarType` supplies the same shared numeric domain and presentation to map and typed-record definitions. Positive-only activation and climate depth use an open zero endpoint; neither the interaction step nor a slider grid becomes a surrogate minimum. Dimensionless numbers also retain their declared increments. The existing field-meaning catalog declares cooldown zero as Off and opening-zoom zero as Native initial view through `NumericDisplay.Caption`. Shared controls and captured information/review projections format these meanings; exact entry, exports, files, and runtime values remain numeric. Complete constructor and paired-profile validation still run after leaf admission.

`SettingsReferences` marks advisory block, biome, biome-tag, and map identities in both map and typed definitions. `SettingsReferenceSources` captures bounded current client registries on the owner thread, builds immutable indices on the shared worker, and refreshes at tag/connection boundaries or deliberate reopening. Tags carry actual match counts, including resolved-empty tags. Unknown or unavailable sources do not invalidate portable optional IDs. Failed or superseded captures publish no partial index, and failures retain an unavailable explanation. BlueMap's dedicated-server map registry is unavailable to a local client editor; no invented client lookup or remote authority fills that gap.

## Owned sources

| Consumer                  | Source and effect owner                                                                                  |
| ------------------------- | -------------------------------------------------------------------------------------------------------- |
| `StartupFeatureForm`      | Existing properties, explicit false and omitted defaults; immutable loader selection; next-process saves |
| `JsonPreferences`         | Existing admitted JSON profiles, staged for their declared startup, world or reload boundary             |
| `TerrainProfileForms`     | Exact generation/shape definitions and their required complete-pair review                               |
| `NativePreferences`       | Actual loaded NeoForge CLIENT or local COMMON configuration; native serializer and callbacks             |
| `HoofprintPreferences`    | Local map settings with actual immutable live publication and map-cache refresh                          |
| `IntegratedSettings.form` | The current native singleplayer host and its actual registered policy                                    |
| `ClientKeyBindings`       | Compat's registered keys in native Minecraft Options; no additional key registrar or file                |
| `ShaderOperation`         | Existing shader assembly and Iris reload through a bounded identified operation                          |

`JsonSettings.Definition` and the runtime codecs remain authoritative. `ReformJsonStore` derives typed map definitions from their declared fields or accepts an exact typed record definition. It validates original input with the existing full domain parser, then applies supported normalization only to the draft. Opening and no-op saving retain original bytes. A changed save preserves CRLF when present and validates the serialized candidate before persistence. Unsupported missing/unknown fields remain errors. An accepted older schema does not imply that its generation identity can open a current world.

`ConfigJson` provides strict object and text-array input independently of any editor. `ProfileJson.object`, terrain/city readers and transparency profiles use it. Preserve duplicate-key rejection, depth limits and exact scalar parsing when changing this seam. `ConfigFile` supplies bounded UTF-8, regular-file and trusted-path checks for runtime loaders. re:form's owned storage handles editing-source revisions, conditional persistence and readback. No render, generation or map callback reads an editor or file per frame.

Nested record parsing qualifies annotation failures with their full source paths. `ReformDocuments` keeps the shared typed decoder and snapshot policy; when an owned record constructor refuses a coupled rule, its decode adapter reuses the complete original JSON parser to recover declared primary/related field issues. It retains generic structural failures when no attributable owner issue exists. This adds no second domain validator or persistence path.

The startup document's bulk default candidate uses this process's loaded choices. This keeps the definition valid when an explicit false admits an unsupported optional target; substituting all omitted-key fallbacks could make the entire owner unavailable. Individual field defaults still mean key omission and use `Feature.defaultEnabled`, subject to complete admission validation. Preserve the distinction in action labels, help and tests; restoring loaded choices is not restoring the original file bytes.

Consumer tests exercise shipped re:form owners and the actual Compat codecs, specifications, and dependency rules. Shared editor/session/presentation mechanics belong to re:form; do not retain a second backend here for comparison. `verify_package.py` rejects retired class names and normal probe/upstream leakage. Historical behavior comparisons use pinned packaged artifacts, with source and runtime qualifications kept separate.

## Native configuration

`NativeFields` inspects actual `ModConfigSpec` bindings without reading a file. `NativePreferences` waits for registrations, then binds each admitted local CLIENT/COMMON owner before client setup. It reuses one cached `ClientRegisteredSettings` across forms and shortcuts. Remote SERVER caches and caller-selected paths are outside this adapter.

Foreign delegation is explicit. `NativeSettingsPolicy` pins Redstone Link GUI's CLIENT/COMMON fields and all supported Dynamic Waters COMMON fields by actual mod ID, version, filename, type and field path. Compat's navigation route remains independent of the native document ID. Native defaults, kinds, choices, ranges and mandatory restart declarations remain authoritative. Unsupported fields or versions fail admission; an absent or disabled integration does not resolve its target. Collection types are declared rather than inferred from an empty native list.

A native file-watch reload can replace the loaded registration context after a successful save. A later save from its earlier capture must refuse, even when the saved values are equal. **Reload saved** preserves a dirty draft and opens conflict review; resolving the chosen values does not save them. Keep the context check and separate submission rather than silently discarding or retrying a draft.

Whole-document validation is additional to native per-field checks. Sky Villages reuses `NeighborRule.Settings` so individually valid minimum/maximum gaps cannot bypass their coupled rule. `ReformDocuments.invalid` preserves structured primary and related field issues. Do not infer attribution from English exception text.

`SettingsCatalog` declares consumer timing. Dynamic Waters generation enters saved water identity; flow, visuals and audio have their inspected native readers, menu creation uses a new view, welcome text uses the next join, and the Tectonic option has a config-load effect on another mod's settings. Native save/readback does not certify arbitrary downstream effects or make callbacks transactional. Sky Villages values are captured by `NeighborConfig.beginServer` and belong to fresh-world identity. Preserve stronger native game/world restart requirements.

Journal-local buttons borrow a caller-closed `DocumentActions` actor from the same native binding. They serialize through its persistence lane, await its receipt and retain errors. Busy buttons cannot submit another action. A source change conflicts with an existing GUI draft; shortcuts do not copy that draft, write an independent file or bypass native validation.

## Reviews and application

`ProfileEditPlan.review` owns generation/shape compatibility. Both exact definitions participate even when one is clean or hidden. It validates the complete proposed pair and chooses a write order whose saved prefixes remain valid. re:form's required scope supplies fresh source checks before each effect, including after an earlier unrelated save. Expected state advances only after observed readback. A proposal with no safe order is refused before persistence. This is bounded conditional coordination, not cross-process atomicity or rollback over an external writer.

Saved bytes, staged requirements, effective values and failures are separate observations. Local startup/new-world/default files use staged owners without a runtime publication or apply-only operation. Hoofprint uses an actual live owner. Native registered configuration reports its native persistence and requirements. A successful save is not generic gameplay-application evidence. Unknown readback requires reconciliation; partial results keep their actual per-document outcomes and newer edits.

`PolicyDefinitions` supplies the exact Wayfinder/search definitions to server registration and integrated forms. `SettingsReload` binds their existing server-thread `SettingsPolicy` through `ServerSettings` and a verified live application. Native command branches and reload aliases share those owners. Authority is checked from the actual command source or current integrated player, connection, level and permission at execution. Stopped/replaced hosts and revoked permissions cannot reuse earlier admission. Save-success/apply-failure remains distinct, and apply-only retry uses qualified saved bytes without repeating the write.

Locator algorithms remain separate from settings infrastructure. `SearchRecipient`, `SearchReport` and shared work budgets bind replies, pages and cancellation to real requests and connections. [Wayfinder development](wayfinder.md) owns those semantics and their native lifecycle checks.

## Runtime consumers

`RenderingPreferences` retains one admitted native CLIENT spec. Island cloud height, void visuals and world-text hooks read its current native values. Cloud bounds use the pinned dimension codec domain, preserve the no-cloud sentinel and retain vanilla mesh invalidation. Text-display and nametag lighting/shadow hooks keep independent choices and native Iris pass/reset ordering. Shader cloud geometry remains outside native cloud-height authority.

`HoofprintPreferences.current()` projects the shared owner's immutable view on the client thread. The map refreshes bounds and step without disk access, clamps an existing scale and retains center/dimension. Initial zoom applies only when there is no remembered connection view. File inspection never replaces runtime state.

`ShaderOperation` calls the existing recipe assembler and `Iris.reload` on the render thread. It retains bounded busy/success/failure outcomes and permits an explicit retry. Failures do not claim rollback of already generated resources. Optional shader classes are reached only after their startup integration is admitted.

## Dependency changes

For a new or updated owner, reconcile `SettingsCatalog`, `ConfigLocations`, the actual codec/spec, declared fields, application timing, feature gate and package metadata together. Inspect native consumers and callbacks before altering timing. Recheck Dynamic Waters field/list-reference behavior and its Tectonic side effect, Redstone Link's exact registrations, Sky Villages' captured values, Iris pass ordering, and native key Options serialization when their dependencies change.

Keep `SettingsInventoryTest` complete over current JSON, properties and pinned native definitions. Native metadata inventories describe kinds and inspected readers; they do not establish live behavior. Qualify the changed binding through an actual Configure or command path, saved revision, real callback/consumer and relevant absent/disabled/wrong-version controls. Re-run the generation guard for saved-world boundaries. [Testing](testing.md) owns invocations; [verification](verification.md#settings-workspace-earlier-02-migration-evidence) owns the earlier workspace migration evidence, and [public-library adoption](verification.md#public-reform-03-adoption) owns the current API-family boundary.
