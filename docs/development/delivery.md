# Delivery generation

`delivery.structure_search` defaults on for the optional adaptation for Aeronautics Delivery Quests 1.1.1. It requires the active island preset and `delivery.chunk_loading`. It separates structure-status admission from the native village locator's worker continuation. Random locations and foreign generators retain their native dispatch. Existing distance and village landing adaptations remain separate.

## Native work and ownership

The native structure radius, retry order, RNG, templates, weights, rewards, route validation, and landing predicates remain authoritative. The adapter does not turn the structure search radius into a block distance or substitute sampled terrain for actual native starts. One owned worker and one queued root task bound dispatch; one structure-status request can be pending per active job. Loaded native holders are inspected only on the server thread, with at most 64 ready-holder checks per tick. Cache misses enter native asynchronous status registration after tick admission; they do not wait synchronously for generation on the server thread.

The job policies are 32,768 status requests, ten minutes overall, and sixty seconds per request. These are explicit admission limits, not native producer maxima or a bound on all downstream generation work. Refusal defers an attempt without shortening the selected route. The 19 outstanding native requests cover the existing eighteen endpoint requests and one settling structure request. Cancelling a private waiter does not cancel the native future or remove its reservation before that future actually settles.

Admit at most four status requests per server tick, keeping only one pending request at a time. Admission can occur in the worker's queued server task; the next tick admits a deferred request when that tick's allowance was exhausted. The actual future registration still runs through the native worker branch. This avoids a mandatory extra tick for every already-completed engine result, including providers whose ready results are not exposed through vanilla's holder map. It does not speculate about future chunks or cancel native work.

Search tickets and endpoint tickets have separate owners. Record ownership before calling a native ticket mutation, so an exception after insertion can still release the ticket. Never remove unrelated tickets. Endpoint neighborhoods remain held until native registration returns or the attempt fails. World unload, requesting-player logout, server shutdown, failure, and expiry retire the corresponding job; late continuations must not publish into a replacement job or reset its generating flag. The adapter closes its worker on server shutdown.

Keep at most the last successful structure-status ticket until the next native read or job retirement. Inspect the native holder before admitting the next request; do not retain an independent chunk-result cache. This avoids immediately discarding native readiness between consecutive reads while keeping ticket and request ownership bounded.

## Qualification boundary

The current engineering candidate passes native public village-route generation, actual quest-file persistence and saved-world reopening, ticket insertion fault controls, and a delayed-result cancellation/successor control. The latter holds a fixture-only proxy, leaves the original native future untouched, and checks admission while retired work is still settling. A minimum current C2ME/NoTick cohort also creates and saves a real quest. These earlier checks are retained as engineering evidence; later current-cohort and lifecycle checks below support default-on candidacy. They do not establish sustained full-pack performance.

The dedicated production cohort without Zfastnoise generates and saves a useful route and shuts down with no owned jobs, reservations, tasks, endpoint leases, or live delivery workers at a 6 GB fixture heap. Its 4 GB counterpart generated the route but then exhausted heap; retain that failed run rather than treating successful publication as whole-run acceptance. Historical biome-disabled diagnostics are separate inputs, not qualification of this cohort. Fixture configuration is explicit; the startup harness no longer imports an installed biome override implicitly.

The separate `--adq-lifetime --adq-expiry` control moves only the disposable job's deadline into the past. The normal server tick must expire that actual job, refuse replacement while its held request settles, leave the original native future uncancelled, and admit a successful successor afterward. This passes on the minimum native terrain/C2ME cohort; it does not replace disconnect, active shutdown, or combined-cohort controls.

The engineering8 current-cohort first-read pair uses identical chunk coordinates and structure status: the original/off path enters a server-thread managed wait, while the enabled path registers the native future without that wait. Both deliberately abort after one read; this is causal evidence, not route success or a timing comparison. All sixteen ADQ runtime classes remain byte-identical to engineering5.

The separate `--adq-lifetime --adq-logout` control removes the actual requesting player through the native player list. It verifies cancellation, refusal while the original native future remains held, uncancelled late completion, a new connection for the same player, and a useful saved successor. Owned jobs, requests, tasks, leases, and workers reach zero. This passes on the minimum terrain/C2ME cohort with embedded native connections; it does not qualify remote client transport or active-stop behavior. Minimum absence and a synthetic future-ADQ metadata guard separately verify disabled class-loading safety and enabled exact-version refusal; they do not qualify an unreleased ADQ binary.

The current no-Zfastnoise production dedicated OFF/ON pair saves the same useful 4.9 km route, with original radius, retry order, template, weight, and rewards. The enabled production integrated client independently saves a useful route and shuts down normally. RANDOM retains its original executor; ANY_STRUCTURE produces and saves a useful native structure route. The latter takes thousands of native status reads: nonblocking admission preserves reach but does not make generation cheap. Foreign generators retain their original dispatch.

Native board packet/codec, ordinary acceptance, cargo assembly, destination completion, rewards, duplicate-payment prevention, saved removal, and unrelated forced-chunk custody pass on the same copied real offer with the repair off and on. The fixture transports the actual Sable body to the original destination; it does not qualify flight. Requesting-player logout/reconnect, active server shutdown, expiry, late-result settling, explicit off, optional absence, and unsupported-version refusal pass separately. All owned resources and workers retire. Three interleaved full-trace/phase-only minimum-terrain pairs retain identical useful offers; this small observer-overhead control supports no general performance claim.

These checks support enabling this exact optional repair by default on its admitted cohort. Explicit false remains authoritative. Remote transport, sustained whole-pack heap/throughput, and broader world-generation performance remain separate qualification obligations. Keep the earlier 4 GB exhaustion and partial observation windows attributable; a later passing route does not erase them.

When updating ADQ or the loader, inspect both calling-thread branches of `ServerChunkCache.getChunkFuture`, the native root and finalization lambdas, `isGenerating` ownership, ticket levels, saved-file ownership, and all required injection counts. Retire the adapter only when the replacement native implementation preserves these behaviors. Do not broaden version guards or injection allowances merely to load a new binary.
