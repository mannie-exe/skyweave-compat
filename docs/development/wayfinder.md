# Wayfinder

Wayfinder uses one server-authorized request per player. The G binding and `/skyweavecompat wayfinder` enter the same path. Configuration and defaults live in the [operator guide](../configuration.md#wayfinder).

## Targeting and authority

`SightRay` clips a normalized ray to the actual dimension build bounds, world border and engine coordinate domain. Its resumable cursor has no distance cap. `WayfinderTrace` consumes bounded cells or LOD bands per client tick and closes its data reader on every terminal outcome. Native loaded collision geometry takes priority; missing LOD columns terminate as missing data rather than empty space. Use the chunk source's non-creating lookup for native availability. `ClientLevel.hasChunk()` always returns true; using it here silently substitutes empty client chunks for distant terrain and bypasses DH.

`Wayfinder` snapshots the authenticated player's eye, direction, dimension and request lifetime. It checks native permission level 2 by default before admitting work and again before teleporting. Legacy tags and scoreboard triggers have no authority. Responses must match the current token and sight ray. Movement, view changes, logout, lost permission and world changes invalidate pending work. Session validation compares the current authenticated player object as well as the UUID/token; packets from a retired connection cannot control its replacement. A physically client-only NeoForge CLIENT spec owns live message visibility. The server sends typed status/stage enums privately to the authenticated requesting operator; no arbitrary formatted text crosses this boundary. A single receipt binds request UUID, exact client connection/world, dimension and monotonic sequence. Terminal outcomes are accepted once. Native configuration saves update the preference immediately; visibility never gates required control packets or grants permission. Pending states are coalesced at forty server ticks. Protocol version 2 uses the distinct optional `wayfinder_v2` payload identity. NeoForge rejects differing versions of the same ID even when marked optional; retaining the retired ID would prevent old/new peers from connecting. Old and new endpoints may remain connected without claiming this capability. Explicit commands retain native fallback output where the peer lacks the channel.

Policy values live in the server-owned `SettingsPolicy`. Each admitted job retains its work/timeout/lookup snapshot. Explicit operator reload affects new requests; reduced caps constrain new native leases while old futures remain accounted. Current access and captured/current hazard exclusions are checked before landing. [Configuration ownership](configuration.md#runtime-policy-ownership) owns revision, authorization, and reload contracts.

A client hit remains a candidate. The server checks nearer loaded terrain, then leases at most four destination chunks and resolves the real target shape and body space. It invokes the native teleport-command event and rejects cancelled or redirected destinations. Failed attempts do not provisionally move the player. This does not prove line of sight through uncached or unobserved terrain.

`WayfinderGeometry` keeps hazard membership separate from collision support. Optional absent block IDs must not resolve to the registry's default air block. There is no support whitelist. The original hit is revalidated before an upward-only support lookup in its column. `placementLookupHeight` defaults to sixteen blocks; zero restores hit-block-only placement. The first safe support wins. Blacklisted supports and fluid-only cells stop the lookup, and the shared 4,096-cell validation budget spans all attempted heights. It does not search downward or accept an inside/underside hit. The existing two-block overlap along the sight ray is separate from this vertical lookup. Placement uses the actual player bounding box, including native scale changes. It bounds collision work to 512 shape pieces and 4,096 body cells per attempt; oversized or overly complex landings fail rather than acquiring unbounded chunks. The world-length surface check clips native AABBs directly: VoxelShape's interior sample at 0.001 of the entire ray can otherwise misclassify a far surface.

When Sable is installed, the core checks its exact 2.0.6 coordinate-frame API. Loaded construct envelopes are conservative unsupported-target boundaries; reserved storage cells and destination chunks are never treated as ordinary world terrain. A new envelope scan before landing rejects intervening constructs. This does not add construct targeting or project a moving hull into terrain coordinates.

## DH boundary

The physical-client adapter targets DH **3.3.3**. It tries leaf sections first, then existing parents through DH's root detail. Public synchronous raycasts wait on futures. The pinned remote provider’s `get`/`getAsync` boundary also queues synchronization for visited cached rows, while its base getter can rewrite old formats or delete corrupt rows. Preview instead reads the native V2 repository and DTO decoder directly, with both compressed DTO and decoded source ownership closed appropriately. A Compat-owned daemon worker admits one actual read through delivery/disposal, including across retired queries, and expires after thirty idle seconds. It does not use DH’s retiring priority executor: that executor can discard queued work without completing its future. Preview requests no synchronization, generation, cache repair or native chunks; malformed stored data reports failure without repairing the row. Normal DH rendering still owns its independent cache updates; this is not an immutable SQLite snapshot.

Each query retains at most two decoded sources, 128 absent-section entries and 256 decoded column observations. World, native wrapper, level and provider identity bind that state. Closing retires the query immediately and disposes retained pooled sources; a late callback closes its result before releasing the shared read gate. Cancelling only a wrapper future would not release actual upstream work safely.

A parent row alone does not establish column coverage. Require an actual column, adequate native generation-step metadata and legal nonoverlapping vertical bands. Native visual compression can omit lower depth: certify only the vertical interval traversed by the ray in the current column, preferring the finest observation covering that interval. Omitted depth and internal gaps remain unknown; try an existing parent only when the requested interval lacks coverage. Null columns, missing rows and incomplete generation stages remain unknown. DH propagates the minimum child generation stage. Coarse material and averaged heights are representative observations, not exact child collision geometry. Thin solid, all-air and partial-parent behavior must be checked against actual importer/downsampler output when DH changes.

The trace preserves native received collisions and the nearest represented hit. A coarse candidate carries its aligned cell extent rather than a fabricated block coordinate. The server derives the ray's interval through that cell and leases only a bounded native neighborhood. It refines the first actual collision across the complete native height in bounded tick slices, then runs the ordinary footing/body/hazard checks. A missing actual collision or a footprint exceeding the existing four-chunk bound reports incomplete; it does not select a farther island. Neither coarse air nor distant client evidence proves a complete native-resolution line of sight through the intervening world.

Raw band heights are relative to native minimum Y. Minecraft build bounds remain authoritative: DH's `getMaxHeight()` names dimension height. Clip the native importer's padding air at the exclusive ceiling, reject solid out-of-bounds data and preserve distinct solid/air bands. Cache eviction changes cost, not the interpretation of a retained source. Dedicated servers register only the common protocol, policy and destination validation. They do not resolve client input or DH wrapper classes. A client without the channel receives a native loaded-terrain command path; unavailable terrain reports the compatible-client requirement explicitly.

## Maintenance and verification

When changing Minecraft or NeoForge, recheck collision clipping, player bounds, upward lookup bounds, teleport-command hooks, native chunk futures/tickets and payload registration. When changing DH, inspect provider read-only behavior, section encoding, pooled source ownership, raw height representation, wrapper identity and shutdown. Requalify the exact optional dependency version before changing its admission pin. When changing Sable, recheck container iteration, world-space bounds, removal and reserved plot membership before admitting the new version.

Use the existing server and client probes. Native column readback alone does not establish a client sight query, a network exchange or validated arrival. Keep those results separate in [verification](verification.md). Fixtures may prepare real corridor chunks and import their LOD data; product targeting must not do so.
