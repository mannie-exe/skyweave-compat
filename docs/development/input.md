# Input ownership

The optional `inventory_profiles_next.text_input_protection` adapter guards IPN-owned shortcuts on the physical client. [Configuration](../configuration.md#adaptation-switches) owns its supported versions and opt-out. Inventory defaults, refill ranking, continuous crafting, and Mouse Tweaks gesture policy retain their existing owners.

## Native keybinding consumers

`NativeInputAdmission` queries NeoForge's registered `KeyMappingLookup`. It neither builds another index nor consumes a click. The native lookup owns conflict contexts, current modifiers, and preference for a matching modified mapping before unmodified fallback. A raw `matches` comparison identifies a key; it does not establish this admission. The adapter is called only at the selected consumers, never as a global replacement or tick-time mapping scan.

`punchy_moves.keybinding_modifiers` applies native admission to Moves' camera, editor, menu, and emote activation comparisons. Its menu-key comparison is a second-press close action. The existing no-screen/player guard still owns gameplay activation. The keyboard dispatch scope suppresses Moves' premature perspective notification, including cancelled dispatches, and restores its previous scope in `finally`. The actual native perspective mutation notifies the upstream controller once after the accepted click. Controller calls outside keyboard dispatch retain their original behavior. No animation, emote, or camera implementation is copied into Compat. Dynamic startup restoration reads the native options key and modifier suffix together; the upstream fallback still handles malformed key tokens. Explicit unassignment, native saving, and resource registration retain their owners. The catalog publication boundary also gives known emote mappings an activity context delegated to their original context. Removed entries retain their saved keys but cannot reserve native modified-key priority; only their own held/click state is released through the native mapping method. Reappearance restores activity without rewriting preferences. Publication replaces one immutable identity set, with no catalog scan during input.

`effortlessbuilding.keybinding_modifiers` retains one fresh natively admitted radial press across the radial screen's deliberate `KeyMapping.releaseAll`. This is necessary because replacing the raw poll with `isDown` would close the menu immediately. The original keyboard or mouse dispatcher completes before that press is admitted. Repeat events do not establish a new origin. Its own radial screen is explicitly marked; actual transitions to other screens, native close/cancellation, window focus loss, disconnect, rebinding, base release, or lost modifier/context admission retire the origin. State contains only the immutable bound key and modifier. Placement, selection, and close behavior remain with the native radial. Undo/redo still consume their own native click queues. A declared modifier is authorized by that native press; Compat removes the additional hidden physical-Control check. With no declared modifier, the existing physical-Control requirement remains. History actions require an active world, focused game window, and no screen. The original packet transport, placement pipeline, history, and server handlers remain authoritative.

`powergrid.keybinding_modifiers` gives circuit tool bindings the actual native editor context and alternate wiring the native in-game context. The editor marker does not replace focused-child handling, hotbar tool selection, or native Use. Its editor context retains semantic Shift, including reverse rotation. Alternate wiring admits fresh keyboard/mouse presses through the native lookup; it retains only the originating key and modifier after the native wire handler actually becomes active. Base or modifier release, window focus loss, another screen, or disconnect ends that owned press through the original handler. Only disconnected local cleanup writes the native flag directly, without sending a stale packet. The original handler remains responsible for wire eligibility and its existing server packets.

Native key tokens, scancodes, and mouse bindings retain the native dispatcher's own supported semantics. A control accepting a numeric code does not prove it can poll that device type correctly. Keep physical-Control fallbacks distinct from NeoForge's configurable platform Control modifier; do not silently change semantic tool modifiers to Command on macOS. Every additional consumer needs its own activation, release, capture, and text-focus qualification.

## Dispatch and activation

`GlobalInputHandler.onKey` and `onMouseButton` update libIPN's pressed/previous-key sets before its private `onInput(NativeInputContextBase)` dispatcher. `IpnInputDispatchMixin` observes that boundary and retires released origins in `finally`. It does not cancel the dispatcher, edit its sets, or consume the original event.

`IpnKeybindMixin` guards `MainKeybind.isActivated/isPressing` and `AlternativeKeybind.isActivated/isPressing`. `IpnTextInput` captures the actual primary keybind identities from IPN's `ConfigScreenSettings` declarations. Alternatives follow their native parent identity. Other libIPN consumers retain native behavior. This query boundary covers IPN's regular handler, cancellable handler, the independent configuration listener's toggles/open shortcut, and direct polling through those owned keybinds. Guarding only `InputHandler.onInput` would miss the other paths.

The native inventory handler has an earlier blanket text-focus check. `IpnInventoryInputMixin` preserves it for keyboard actions and mouse events outside active slots. Deliberate slot mouse events may reach the owned binding checks, which still reject keyboard chords belonging to text. The exception neither directly sorts nor consumes the original event.

Text-owned keys remain suppressed until native release processing completes, including release-triggered chords and closing the editor while a key is held. Window focus loss and disconnect quarantine held origins; they do not clear upstream keys or manufacture a release. Active native keybinding assignment retains deliberate capture. Opening a configuration screen alone does not exempt its text fields. Shutdown clears local policy state. Retained state contains bounded key codes and configuration identities, with no screen, player, world, or chunk references.

## Focus and mouse ownership

Focus follows one native focused-child path, bounded to 32 nodes with cycle refusal. Supported text owners include visible focused `EditBox` and `MultiLineEditBox` widgets, native book/sign editors, and the visible recipe-book search field. `RecipeSearchAccess` reads the latter because it is outside the screen's ordinary focused-child path. libIPN screens use their own focused-widget path and public text-field state; their configuration search has an explicit owner. The optional admitted EMI public `isSearchFocused` API is resolved once; no reflective widget walk runs during input or rendering.

A focused text widget does not disable every inventory interaction. Mouse-only and modifier-plus-mouse shortcuts can act over a real active inventory slot. Letter-plus-mouse chords remain protected while typing. The adapter checks the current pointer against native slot geometry through `IpnContainerAccess`; a previous render's stale hovered slot cannot authorize a click over text. Direct toolbar clicks keep their native button path.

Custom editors that neither use these native focus contracts nor expose the admitted search API need separate qualification. The adapter does not infer text ownership from screen class names, scan whole widget trees, or promise universal IME/input-layout support.

## Dependency updates

Inspect both IPN and libIPN artifacts before changing their exact gates and compile-only hashes. Recheck primary/alternative keybind methods, declaration ownership, configuration-listener registration, pressed/previous-key timing, assignment, release and polling paths, native/libIPN text focus, and window callbacks. Search the new IPN bytecode for all activation/polling consumers; a new direct dispatcher query may need a different boundary. Verify the optional EMI API and metadata separately. The compile-only Kotlin standard library matches the qualified optional runtime's API; Compat does not bundle it. Disabled or server-side admission must resolve none of these client targets.

For Moves, inspect every camera/menu/emote comparison, dynamic registration and saved-key restoration, raw perspective producer, and the native perspective consumer. Verify controller cleanup with active shoulder/free-camera state, rather than only an idle first-person control. For Effortless, inspect its radial hold and close callers, native screen key resets, input types, modifier fallback, and placement/undo consumers. For Power Grid, inspect every enum binding caller, registration context, editor focus and semantic modifiers, alternate-wire state and packet writer, and native Use/cutting paths. Requalify both release orders before changing a comparison; admitting a press without preserving its release can strand an upstream mode. Recheck the native lookup and dispatcher release semantics when updating NeoForge. Preserve actual callbacks and state writers; a new public method or matching descriptor alone does not qualify those contracts.

Retire the repair only after an unmodified supported release passes the same typing, nested-focus, explicit mouse, capture, and lifecycle controls. Keep the independently owned defaults/refill work separate.

## Qualification

[Testing](testing.md#settings-refinements-and-input-consumers) owns runner inputs and scenarios; [verification](verification.md) owns qualified artifacts and limits. Use the actual dispatcher, native buttons, and original inventory/server transport. Distinguish activation counts, native event admission, client prediction, authoritative custody, and persisted readback. A failed launch cannot qualify input behavior.

The fixtures use synthetic event delivery and explicitly scoped physical polling. They do not qualify OS composition, every keyboard layout, or arbitrary custom widgets. Complete mod-set coexistence, authored input settings, and targeted optional-provider controls retain their separate receipts. No personal settings or credentials are copied implicitly.
