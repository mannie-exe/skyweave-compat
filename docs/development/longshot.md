# Longshot adaptation design

This is an implementation design, not a list of installed features. Longshot concerns expanded projectile, rope, and attachment interactions in Create: Skyweave. The existing `throwable_rope_connector.range_limits` adaptation repairs startup configuration; none of the proposed keys below is implemented by this document.

Keep current pack ranges: connector hand 16, handheld 64, mounted 128, Simulated rope ceiling 255, Skybound default rope 64, plunger separation 64, pulley 512, and ejector 64 blocks. Longer hypotheses remain owner decisions. Ejector chains are intentional. Static configuration belongs to the pack; optional runtime repairs belong here. No world-generation revision, global reach increase, renderer rewrite, or forced view-distance increase is required.

## Evidence and priorities

Compat main uses public re:form 0.3.0 and admits Simulated 1.3.3 for the existing connector range repair. The findings below originated on the earlier Simulated 1.3.2 cohort; they are historical source observations, not qualification of the proposed projectile and movement adapters on the current runtime. Freeze the actual Compat, library, target binaries, and authored pack settings before implementing or testing these designs. The pack owns its exact installed selections.

The original inspected baseline was Minecraft 1.21.1 / NeoForge 21.1.265, Throwable Rope Connector 0.4.3, Simulated 1.3.2, Sable 2.0.6, Skybound 1.1, Create 6.0.10, DH 3.3.3, SSRD 1.8.8, and Big Cannons 5.11.7. Rebind hooks to the selected released binaries before implementation. Exact local source/bytecode observations establish mechanisms, not an exploit reproduction, live-shot result, or performance qualification.

The manager treats a nonpositive loaded-entry cap as unlimited; preserve that sentinel and distinguish this aggregate admission cap from per-tick throughput. Actual generation amplification and cleanup under the installed optimization stack remain unmeasured. Review this existing owner before adding tickets.

## 1. Connector flight integrity

Keep launch origin and effective range immutable for each shot. Replace the zero-vector initialization sentinel with explicit validity; world origin is a valid location. Validate finite coordinates, legal build/world bounds, effective zero ceilings, and actual hit position before placement. Projectile radial range and the later world-space rope endpoint check remain separate, with their native inclusive/exclusive semantics. Moving a launcher must not move the historical launch origin.

Add a small per-flight state: launch UUID, producer kind, world/session and source incarnation, actor UUID where present, effective radius, and custody state. Terminal states are committed, refunded, or cancelled without a refund. A terminal flight cannot run placement or refund again, including after `super.tick`, repeated hits, an event callback, or reload. Use projectile-owned state and source-local references rather than an unbounded static job history.

At launch, classify player success-only ammunition as unpaid, native consumed ammunition as prepaid with its exact one-item component stack, creative as no-refund, and dispenser as its own prepaid producer. Determine consumption from the actual native path, not owner absence or the visual `getItem` stack. Preserve success-only behavior: reserve the actual item immediately before placement, finalize on success, and restore that exact escrow on cancellation/failure. This closes the event/reentrancy gap between the native availability check and later consumption. Suppress the native second debit only inside that scoped transaction. Never use a fresh default item as proof of custody.

Coordinate mounted pending ammunition with the same per-flight identity. Transfer responsibility exactly once; a block-entity refund flag and projectile must not both own the same prepaid item. Admit one active mounted flight per launcher unless a tested multi-flight model is later selected; repeated trigger attempts receive a busy result without another projectile, ray, or debit. This is an intentional behavior change that must be documented. Persist active custody and incarnation consistently across save/reopen; legacy in-flight saves without enough provenance cannot fabricate escrow. Define a conservative legacy refusal/recovery result and test it before shipping.

At impact, resolve the same launcher incarnation and sublevel identity, not merely the same position/type. Replaced, dismantled, or inaccessible sources refuse. A rider-origin shot retains its initiating actor and applies native player placement/protection checks at the actual target. Do not substitute an arbitrary online player for unattended automation. Existing actorless automation stays a separately qualified native path; extended automated placement is held until its protection/ownership policy is selected. Do not quietly disable ordinary redstone fire to solve that open question.

Revalidate ammunition, source, permission, target replaceability, fluid/support conditions, and range immediately before mutation on the server thread. Invoke the native placement and rope connection once. If a later connection fails, remove only the connector placed by that transaction if its identity/state still matches; never delete an unrelated replacement or undo third-party event writes blindly. If exact rollback cannot be established, surface the partial result rather than report an ordinary clean failure.

Initial implementation seams are the three native launch producers, projectile `tick`/`onHitBlock`/`failAndReturn`/save methods, placement `placeConnectorAndGiveRope` and its debit/give boundary, and mounted `fireInDirection`/`connectToPlacedConnector`/failure handling. Prefer narrow wrappers and owned transaction helpers. An overwrite of the whole foreign item or projectile is not required by the design.

## 2. Skybound movement validation

Intercept `PlayerMovementC2SPayload.process` before its queued mutation; check again on the server thread against the current sender/session/dimension. Reject non-finite values before constructing `Vec`, because NaN-to-zero substitution is itself a world-origin teleport. Preserve the sender-ID check, entity liveness, current native teleport acknowledgement, and valid world bounds. Packet claims do not create movement authority or load chunks.

Use server hook/controller transitions and issued detach state to establish eligible motion. Include `AIR_FRICTION`, motor/rocket customizations, riding/spectator changes, hook cutting, death, and authoritative teleports. `PhysicsUpdateC2SPayload` is client-reported telemetry/advancement data, not permission to activate movement. Revoke retained authority on the corresponding native terminal event, not an arbitrary elapsed timer. Bound storage to live players and their active transition records; never scan all players or all hooks for each update.

Qualify the ordinary native move-packet stream first. The preferred reconciliation is to keep collision, moved-too-quickly checks, teleport confirmation, and chunk eligibility with the native movement owner, applying only a justified grapple-specific bridge. Compare suppressing redundant custom position writes with routing admitted motion through native validation. Do not synthesize vanilla move packets, remove `resetPosition`, or cap all players at a guessed speed without this comparison. Current client velocity caps are not an authoritative server budget, particularly on moving Sable bodies.

Coalesce redundant same-tick updates only after tracing native call order. Define bounds from admitted mode, actual customization, server ticks, and body-relative motion, with separate vertical/falling behavior and reported correction reasons. A malformed burst must cost bounded work and cannot move terrain loading or spam one log per packet. This task does not attempt a complete new anticheat or authoritative rewrite of every grapple physics equation.

## 3. Queries and ordinary projectile visibility

Loaded-only query admission precedes ballistics or optional loading. On the server thread, use `getChunkNow` for availability, accounting for NeoForge's `currentlyLoading` transitional result: require the chunk's usable native state, not a non-null handle alone. A ray/query has at least four outcomes: hit, complete miss, unavailable terrain, and invalid/failed query. Unavailable data must not be treated as empty air or an estimated safe attachment.

For mounted fire, perform existing cooldown, active-flight, connection, actor, and ammunition checks before `fireFromRider` invokes its long reticle ray. Retain the final native recheck before spawning. For a moving projectile, validate the swept segment and collision dependencies, including endpoints and relevant neighboring shape reads. Iterate crossed chunks, not the entire enclosing X/Z rectangle; use overflow-safe coordinates and a measured maximum admitted work footprint. Do not scale Wayfinder's intentionally small destination lease to a long diagonal bounding square.

Sable's native `BlockGetter.clip`, projectile distance/position adjustment, Create ray helpers, and Skybound's manual branch remain the frame authority. A plain loaded-only `BlockGetter` would bypass Sable's `Level` branch. The implementation gate is a disposable native comparison proving that the chosen scoped query boundary preserves native world/plot hit identity and makes zero missing-chunk requests. Compare guarded native delegation over a fully admitted footprint with a native frame-aware per-world/per-sublevel adapter; choose only the branch that passes. No global getter interceptor, thread-wide replacement of all rays, or silent terrain-only fallback is authorized by this design.

For connector visibility, retain the ten-tick update interval until actual jitter measurements justify a change. Extend the selected entity's effective tracking radius from its valid launch policy, then qualify client distance tests and a culling box that includes the rope's source and projectile. Never change all `ThrowableProjectile` instances. The native tracked-chunk and player-view gates remain. A shot outside that interest region is explicitly not solved by this phase, even if DH draws its destination.

The native flight radius is not currently synchronized as custom entity data. Do not assume it is present on remote clients or append foreign metadata that breaks unmatched clients. If exact client bounds need a descriptor, negotiate a small S2C tracking descriptor keyed by world/session, entity ID, and UUID; send at launch/start-tracking, not every tick. Reject stale/replaced entities, drop state at stop-tracking/disconnect/reload, and bound it to currently tracked flights. A client without this optional capability retains native presentation. No new distant terrain or block packets accompany it.

## 4. Flight profiles and other tools

Keep current 16/64/128 connector settings during the first repairs. If a mounted 255-block horizontal target is later selected, speed 3 and ±30-degree pitch do not reach it at equal height. A discrete stationary-air calculation suggests speed about 4.23 at 30 degrees; this is a prototype input, not a final setting or observed shot. A 255-block rope ceiling is also exclusive at the actual endpoint check, and muzzle/endpoints consume different distances.

Prefer a native visible projectile with preserved sweep/impact handling. Target rays can choose an arc; they do not authorize instant placement through the path. Use a bounded discrete solver matching the selected gravity/drag order, with explicit no-solution results and range/height/obstacle controls. An arc preview is an estimate unless the entire collision path has authoritative coverage. Do not add a new permanent per-frame whole-range ray merely to display it.

Skybound already exposes speed, gravity, and per-item rope customization. A longer-line prototype can begin as native data/configuration, preserving existing customized items. For reference, the same simplified model gives speeds about 3.54/4.19 for 96/128 equal-height blocks at 40 degrees with gravity 0.1; moving actors, wrapping, water, and manual Sable flight remain separate tests. Hook tracking/render behavior differs from the connector, so do not copy its distance patch wholesale.

Plunger separation remains native `equipment.maxPlungerLauncherRange`. If longer recovery is selected, adapt only the hardcoded 48-block correction ray in `getCorrectionInfo`, keeping barrel obstruction and Sable projection. Choose a finite correction distance within the effective separation policy; zero disables admission without invalid normalization. Demonstrate benefit with off-axis/muzzle cases before adding an adapter. Native pair removal already releases constraints; prove that behavior rather than reimplement it. Pull-vector saturation, force frames, and stronger towing are separate policy/physics investigations.

Keep ejectors at 64 and pulleys at 512. Preserve Create's native solver and pulley world-depth restrictions. Potato ammunition and Big Cannons munition/propellant data own their profiles. Big Cannons' AP-shell `drag: 0.01` is not a vanilla 0.99 retention field; its propellant also changes stress, recoil, and spread. Preserve enabled Sable projectile velocity inheritance exactly once. Use 256/512-block cannon scenes as measurement cases, with 1024 separate; no universal range cap, charge increase, damage rebalance, explosion rewrite, or additional artillery chunk loader is selected.

Audit Big Cannons → Ritchie’s Projectile Library → `ChunkManager` as part of this phase. Reproduce its EMPTY→FULL promotion on saved FULL, saved proto, and missing terrain with native switches ON/OFF, observing the effective native queue/ticket/generation path. Compare finite native limits and record queue length, chunks processed per tick, promotion latency, generation, entity-ticking wait, expiry/unforce, smoke lifetime, and saved pending work on reopen. Do not describe its current implementation as no-generation. A proposed independently optional `ritchiesprojectilelib.saved_chunk_loading` repair must adapt this producer rather than install a competing loader, preserve admitted saved-world behavior, and refuse proto/missing data before promotion when the selected policy is saved-only. Its asynchronous promotion/dependency proof is a gate; a blanket loaded-only replacement would silently remove native artillery reach and is not the selected fix. Do not change these native switches without an explicit pack-policy decision.

## 5. DH candidates and optional residency

This phase has explicit research gates. Existing `ConstructCoverage` qualifies presentation through uploaded buffers, owner identity, intervening columns, and native meshing. `DhWayfinderColumns` can read stored coarse columns with bounded asynchronous ownership. Neither is a server collision oracle. Reuse pure geometry or provider boundaries only where their contracts match; neither the renderer's convex footprint nor Wayfinder's deliberate FULL-chunk loading can simply become a projectile loader.

Use DH only for an optional client indication of a candidate or uncertain corridor. Bind hints to the actual level/resource/renderer generation, distinguish confirmed empty from unknown, and clear on teleport, dimension change, reconnect, and reload. A server request contains an intended action and finite target hint; the server derives its legal origin, range, actor, permissions, and required collision regions. Client coverage does not raise the player's block-interaction reach.

Investigate three distinct policies: already usable terrain; asynchronous residency for existing saved FULL chunks; and generation of missing terrain. Start with the first. The latter two are not enabled by this plan. Vanilla's false future flag is not a saved-only loader, and `ChunkMap.isExistingChunkFull` itself can join disk reads. A saved-only prototype needs asynchronous status preflight, a complete bounded dependency footprint, and proof that both vanilla and the installed C2ME path do not generate missing neighbors. If the native promotion requires missing work, refuse before ticket creation; do not rename it existing-only.

Model later deliberate actions as admitted → checking residency → ready → in flight → committed/refunded/cancelled. Own tickets by action/world generation, deduplicate overlapping chunks with reference counts, and retain actual futures until terminal even after cancellation. Teardown removes that action's interests without pretending an in-progress native load was rolled back. Distinguish FULL availability from block/entity ticking and active Sable physics; loading one destination cannot simulate an unloaded rope corridor or dormant construct. Unknown active-physics residency refuses the action.

Before accepting this phase, measure corridor size and dependency amplification, concurrent actions/players, queue fairness, load latency, retained memory, disk/network work, and ticket cleanup. Select quotas from those measurements and expose admission/backpressure reasons. Speculative previews do not request tickets. No synchronous joins on the server thread, global simulation-distance increase, indefinite physics activation, or timer that reports success when work is incomplete. Cancellation, death, teleport, disconnect, server stop, and replacement invalidate pending results before mutation.

## Implementation and qualification order

1. Freeze exact products and reproduce the original connector ordering/custody/source-replacement conditions in a disposable native probe. Retain the startup repair's lower/zero-ceiling controls. No ballistic changes yet.
2. Implement connector flight integrity with transaction and native integration checks. Review player, creative, dispenser, rider, and automatic producers separately; unchanged automation remains an explicit retained boundary.
3. Reproduce Skybound's packet validation gap locally; qualify native movement versus the custom stream, including post-detach air friction. Implement numeric/authority and lifecycle checks, then prove legitimate movement before enabling the repair by default.
4. Qualify and implement loaded-only query admission without losing Sable/Create hits. Fix ordinary tracked-range connector presentation. The two adaptations have separate gates; neither authorizes new loading.
5. Present observed range/height and cost results for flight/plunger proposals. Author only owner-selected native settings or experimental adapters. Keep new profiles off until their actual shot/attachment/return behavior passes.
6. Qualify the existing artillery producer and its saved-only repair before sharing any loading policy. Run bounded DH/residency prototypes only when selected for that implementation pass. Choose measured policies or explicitly retain the saved-only/missing-terrain/remote-physics deferrals. This is not a prerequisite for shipping independent verified integrity repairs.

Extend the existing `src/probe` artifacts and startup/rendering harnesses with dedicated Longshot scenarios; new scenario names are implementation work, not existing CLI flags. After Java changes, run `./gradlew check build`, then packaged minimum, OFF/absent, enabled, and relevant unsupported-disabled fixtures. A build or title boot alone does not qualify action behavior. Keep the observer out of release contents.

Performance acceptance starts with deterministic requirements: zero new load work in loaded-only modes, no per-frame database/whole-world scans, work proportional to crossed query cells/live flights, and no retained growth after repeated sessions. For latency and throughput, collect repeated paired workloads and their measurement noise before selecting numerical regression limits. No unmeasured millisecond budget or blanket increased update rate is adopted here. Document a fix that is correct but too costly as held rather than silently weakening its behavior.

## Maintenance and handoff

Keep one owner per range, feature, and outcome. The pack's [progression review](https://github.com/mannie-exe/create-skyweave/blob/main/docs/development/progression.md) owns current gameplay defaults; its Longshot index routes related work. This design owns proposed runtime seams. Update native fixtures, supported versions, credits where applicable, and retirement checks together. Inspect released replacement behavior with the adaptation OFF before removing a repair.

Store exact source identities, commands, compact consequential reports, and remaining qualifications privately; do not commit downloaded JARs, decompiled code, worlds, or logs. Normalize only affected tools/docs and preserve unrelated UI/Atlas work. Publication, personal client/server synchronization, and world changes require their own selected authority. Implementation completion is not implied by reifying this design.
