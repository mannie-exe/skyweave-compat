# Skyweave: Compatibility Patches

Optional terrain, gameplay, and rendering adaptations for Minecraft 1.21.1. Every adaptation has a startup switch. The Skyweave modpack is not required.

## Installation

Requires **Java 21, stable NeoForge 21.1.265 or later in the 21.1 series, and re:form 0.3.0**. [Download Compat](https://github.com/mannie-exe/skyweave-compat/releases) and install the separate [re:form 0.3.0 library](https://github.com/mannie-exe/reform/releases/tag/v0.3.0) on both applicable sides. Install the same Compat version on the client and server. `gradle.properties` pins the public library used to build this release; [dependency admission](docs/development/dependencies.md) separately defines the supported stable API family, `[0.3.0,0.4)`. A staged repository is needed only when deliberately building against an unpublished library candidate; see [publishing](docs/publishing.md#shared-settings-dependency).

No content mod or modpack is required. Native-terrain Wayfinder is available without optional mods; dependency-specific adaptations activate only when their targets qualify. Use Compat on the client for rendering fixes, and on both sides with matching configuration when using the expanded island preset. [Release notes](RELEASE_NOTES.md) describe the changes and update limits; [configuration](docs/configuration.md#adaptation-switches) owns exact optional versions and switches.

Edit `config/skyweave/skyweave_compat-features.properties` before startup to disable unwanted features. Changes require a full process restart. Disabled adaptations select no target mixins, callbacks, or data packs and do not constrain target versions. An enabled adaptation activates only when its full dependency combination is present on the applicable side; unsupported active combinations fail clearly. See [all switches and supported combinations](docs/configuration.md#adaptation-switches). [Encounter rules](docs/configuration.md#encounter-rules) explains the native/per-emission choice, mutual-exclusion requirement and local-water scope.

Remove Veil Iris Fix when enabling the incorporated framebuffer adaptation. Remove Sky Village Neighbors when enabling Skyweave: Compatibility Patches' village adaptations. Upstream mods retain their own dependencies. Create/Propulsion ore IDs are optional members of the relative-placement tags, not required mods.

No world preset is selected automatically. To use the expanded terrain, install Sky Archipelago and create a new world with **Skyweave Islands**, or set `level-type=skyweave_compat:islands_v1` before creating a dedicated-server world. Do not change an existing save's generator or recorded generation configuration. Initial shared spawn recovery selects a safe companion island. It preserves mature world spawns and personal beds; no custom team-island allocation is included. The optional Nether-access policy blocks native portal activation and entry in marked worlds, including singleplayer, while preserving ordinary fire and stored data. Ordinary Sky Archipelago worlds receive only applicable enabled adaptations. With Dynamic Waters installed, set `Generation.normalRiverMode=VANILLA` and `mountainRiverTunnels=false` before creating a Skyweave world; keep both native river/lake flags off. The [configuration guide](docs/configuration.md) owns these settings. Ordinary worlds keep their upstream policy.

The rendering adapters have background checks and native macOS shader, Ponder, balloon, and single-block glass comparisons. The original flickering/gapped airship shadow report remains unresolved; this is not a general shadow correction. The Analog Audio registration fix likewise does not establish moving playback or GUI behavior. See [verification](docs/development/verification.md) for exact scope.

[Playback synchronization](docs/development/audio.md) and [construct grave recovery](docs/development/recovery.md) are separate adaptations. They preserve upstream media and inventory ownership; neither requires island generation. Recovery keeps its metadata in YiGD's saved grave records.

The optional Curios/Accessories break-notification repair lets the equipment layer complete its native replacement callback when an equipped item breaks. Item durability, removal, and notification ownership remain native. This is independent of the opt-in slot-binding bridge and does not change glider flight or item-use policy.

The tested Curios 9.6.0, Accessories 1.1.0-beta.54, and Accessories Compatibility Layer 0.1.13 combination also needs the opt-in `accessories_compat_layer.curios_bindings=true` bridge on both sides. It defers entity-slot binding until server datapack tags are available. Without it, the native layer can fail while applying its Curios entity-manager injection. The modpack already selects this switch; standalone installations must choose it explicitly. See the [configuration matrix](docs/configuration.md#adaptation-switches) for the exact version spellings.

See [redstone editing and gate behavior](docs/development/redstone.md) for relocation limits, analog signal changes and pack-owned resource fixes.

Shader recipes can assemble qualified shaders on the client before Iris loads them. The [rendering guide](docs/development/rendering.md#shader-assembly) covers inputs, ownership, caching and supported patch operations. No recipes are installed by this mod itself.

## Linear Bearing

Independent switches repair dedicated startup and gum drops, passive-guide braking and recovery, magnetic/spring kinetic transmission, and gyro sensing. Links use Create's real source and stress network. The gyro supplies a signal with zero stress capacity. Linear Bearings Fix 1.0.3 can remain installed; Skyweave: Compatibility Patches defers its overlapping startup/drop repairs. Read [machinery contracts and dependency ownership](docs/development/linear-bearing.md) before changing or removing these adapters.

Optional Ponder scenes explain assembly, motion, braking, recovery, transmission, and sensing. Jade shows actual brake/link state with extra detail on demand. Both integrations can be disabled independently; neither makes Ponder or Jade a mandatory dependency.

## Colorwheel

Colorwheel supplies Iris-aware Flywheel backends for compatible shaders. It does not replace the framebuffer, single-block-pass or moving-light adaptations. With Colorwheel installed, separate client switches release unused OIT texture slots on unsupported renderers and extend construct material annotations to its terrain/emission protocol. Ordinary world annotations and backend selection remain Colorwheel's responsibility. See [rendering](docs/development/rendering.md#colorwheel) for boundaries and updates.

## Moving lights

With Sable Dynamic Lights and LambDynamicLights installed, independent client adaptations repair the selected Sodium API, keep transient illumination out of integrated-server lighting and clear Create light owners when leaving a world. Neither requires the island preset or Iris. These are optional repairs, not another lighting engine or a general cabin-occlusion fix. See [lighting](docs/development/lighting.md) for dependencies and known limits.

## Wayfinder

Press **F12** while looking at terrain, or run `/skyweavecompat wayfinder`. Rebind the key in Minecraft Controls. Operator level 2 is required by default; the server owns access, hazards and work limits. A successful warp preserves view direction and has no cooldown by default. Press again or use `/skyweavecompat wayfinder cancel` to cancel a pending request. Diagnostic messages default off. Enable **Debug messages** under **Maps → Skyweave: Compatibility Patches** to see private local feedback immediately, without restarting either endpoint. The optional cooldown uses ticks; zero disables it. Placement checks the hit surface first, then up to sixteen blocks above it in the same column, without searching downward.

There is no configured distance cap. Native loaded terrain works without DH; distant targeting requires a compatible client with DH data along the sight ray. Available coarser data can supply a candidate for bounded native refinement; unobserved space remains unknown. A candidate is checked against actual destination collision geometry before teleporting. Unsafe footing, obstructed headroom and changed terrain leave the player in place.

See [Wayfinder configuration](docs/configuration.md#wayfinder) and [targeting and verification boundaries](docs/development/wayfinder.md).

## Distant terrain

DH generates and renders distant terrain through its ordinary pipeline. Skyweave: Compatibility Patches adds focused lifecycle fixes and optional per-save cache isolation; it does not provide a separate terrain predictor. For supported Sky Archipelago saves, cache isolation defaults on. It selects a per-save namespace without moving or deleting older cached terrain; explicit false retains upstream keys. See [DH configuration](docs/configuration.md#distant-horizons) and [integration boundaries](docs/development/lod.md).

## Journal

With Questlog installed, conditions wrap and rewards can be inspected before an entry is complete. Separate tabs preserve access to both. Scrollbars use the content length; narrow windows show one section at a time. Item imagery and condition symbols are controlled through an attached Settings bookmark, alongside notification preferences. Questlog still owns objectives, progress, reward grants and replaceable interface textures.

Journal notifications announce first observed objective progress and completion, not prerequisite unlocks. Completing an entry immediately suppresses its start notification. Reward collection remains explicit. The interface and notifications work on clients connected to ordinary Questlog servers; invalid reward-request protection requires Skyweave: Compatibility Patches on the server. See [journal settings](docs/configuration.md#questlog) and [contracts and limitations](docs/development/questlog.md).

## Island terrain

**Skyweave Islands** uses a build range from Y=-128 through Y=767. Clusters have large anchor islands surrounded by smaller companions. Default anchor height targets are 250 to 400 blocks, with placement fitted to leave floor clearance and building headroom. Ore placement, large iron/copper veins and classic cave carvers use island-relative heights rather than vanilla world altitude. The preset retains stacked exterior terrain and offers baseline, noise-cave and hollow interiors with separate controls for openings and native carving. Sky Archipelago 1.4 supplies the exterior shapes. An optional Dynamic Waters adapter supplies island-local rivers and lakes while the native planner stays off. Fragment fringes add detached outer terrain without consuming the main body. Optional floating-ocean settings add coastal outlets to native wet profiles; falling perimeters remain opt-in and the global ocean stays off. Ancient Cities fit inside Deep Dark hosts, including suitable hollow interiors. Normal and noise-cave hosts permit limited peripheral exposure while protecting the core. Structure lookup resolves relocated starts instead of rejecting them from their original source biome. Vanilla terrain systems are not all reproduced; the [coverage limits](docs/development/terrain.md#feature-coverage-and-limits) describe ocean content, fluids and native feature behavior.

Rare special Deep Dark islands have a deepslate body, coherent sculk surface and sheltered cavern openings. Natural vegetation and passive spawning are excluded there; player farming, brought animals and native Warden mechanics remain available. Surface coverage and the small sensor/catalyst/shrieker budgets have separate [configuration](docs/configuration.md#island-outlines-and-fractured-terrain). An Ancient City may fit naturally, but is not required or forced.

Climate uses each natural contributor's altitude reference instead of treating every high island as a mountain. Underground biomes use native climate selection with island-relative depth; ores keep their separate shared geological frame. Server-owned climate metadata supplies client weather and the selected Iris precipitation behavior without sending a world seed. Separate optional water adaptations use local layers for animal rules and Dynamic Waters floes; Sable temperature queries can follow a construct's parent-world position. Physical light, collision, water and native cold-biome rules retain their own coordinates. See [terrain contracts and coverage](docs/development/terrain.md) for consumer boundaries.

The default candidate grid is 2400 blocks, with up to 750 blocks of displacement in each horizontal axis. Accepted centers do not follow fixed spacing; activation, biome eligibility, clearance and island shapes affect actual travel distances. See [configuration](docs/configuration.md) for controls and [terrain](docs/development/terrain.md) for implementation limits.

## Placement

Ground villages use bounded island fitting, contributor-aware terrain blending and shallow foundation completion. Natural source material is captured before neighboring features; final physical contacts are checked after feature closure. Water, cavities, void and unexplained changed materials cannot become support. The default complete-building policy may reject an old candidate and try another; it preserves encounter allowances rather than guaranteeing every former layout. Static floor embeddings and native scaffold legs can receive qualified support without replacing their contents or furniture. Authored damage and valid clear spaces remain distinct from missing foundations. Resource-authored swamp soil can follow the original island palette. Conflicting leaf decorations can be omitted before they cut a building’s support, and qualified native mangrove roots are kept out of protected foundations. Local contact and doorway checks do not guarantee that every donor road forms a navigable village-wide network.

The separate floating Sky Villages rule requires at least **64 blocks** between the village's full horizontal bounds and predicted island terrain. It also requires a sampled terrain column within **128 blocks** belonging to an island with a native radius of at least **96 blocks**. These distances are measured between block columns, not from the village center.

The expanded preset shifts villages into its island altitude band and assigns each archipelago zero to three villages, weighted toward zero. Buildings and loot remain unchanged. Biome and terrain rejection can reduce the actual count. The neighbor rule does not move villages onto islands or create roads. Ordinary Sky Archipelago presets keep their original height and frequency. Existing generated villages and regular villages are unaffected by the neighbor rule.

The host search uses a 16-block grid. It may miss a narrow eligible part of an island and reject that candidate. Clearance checks every column in the exclusion band, so that approximation cannot admit a village overlapping terrain. Terrain predictions do not include later structures or player-built blocks.

## Structure search

Operators can verify structures without blocking a synchronous `/locate` search:

```text
/skyweavecompat structures search 24000 family=villages
/skyweavecompat structures search 24000 structure=ctov:medium/village_plains
/skyweavecompat structures search 24000 structure=#minecraft:village
/skyweavecompat structures status
/skyweavecompat structures page 2
/skyweavecompat structures cancel
```

Use one family, registered structure ID or structure tag. Managed queries prioritize eligible cluster sites; loaded and saved starts remain discoverable independently of current placement rules. Results contain verified native starts; click coordinates to prepare a teleport. Where native placement has no meaningful altitude, the displayed Y comes from the saved start's bounds. Nothing teleports automatically. The search continues through the selected radius without a whole-search time limit, retains up to64 nearby matches and pages ten at a time. One structure search may run per server; its requester owns cancellation. Background batches retain their progress; finishing one memory batch does not end the query.

Both `islands` and `structures` show periodic progress while running. Players see action-bar updates; console users receive less frequent messages. `page` opens the first results page. Empty searches show an explanation instead of a blank page; an unfinished structure search does not establish absence. Island results are planned centers, while structure results are verified native starts.

Verification can generate and save early chunk metadata. It requests `STRUCTURE_STARTS`, with at most two native requests at once, and does not deliberately generate full terrain. The memory-batch setting controls retained membership records, not total coverage. Larger queries use job-owned temporary indexes, with all index I/O on background workers and cleanup at retirement. Only an exhausted supported search domain is complete; unavailable placement or storage coverage remains **partial**, not proof of absence or of the nearest possible structure. Existing `candidateLimit` values migrate to `membershipBatchSize`; the retired `timeLimitSeconds` value is not applied. Loading a legacy file does not rewrite it. Unsupported placements, including concentric-ring strongholds, are reported explicitly. In marked worlds, the default-on structure-command policy replaces `/locate structure` lookup with an editable bounded-command suggestion. `/locate biome`, `/locate poi`, exploration maps and direct native callers retain their behavior; synchronous callers can still be expensive. Disabling the policy or using an unmarked world preserves native structure commands.

Search budgets live in `config/skyweave/skyweave_compat-search.json`; publish changes with `/skyweavecompat settings reload search` on the owning server. New searches use the updated budgets. They do not change terrain identity. See [search limits](docs/configuration.md#structure-search) and [maintenance](docs/development/terrain-variation.md#structure-discovery).

## Main-menu identity

The default-on client adaptation adds one footer line while preserving Minecraft, NeoForge/mod count, ModernFix and other existing lines. A recognized Resource Patches identity shows `Create: Skyweave <pack version> + Compat <installed version>`; development builds use `DEV`. Otherwise it shows `Skyweave: Compatibility Patches <installed version>`. The pack baseline and actual loaded Compat version remain separate. This does not change early loading screens or network branding.

## Configuration

Open **Mods → Skyweave: Compatibility Patches → Config** for searchable gameplay systems and mod pages. Setting links jump within the selected page; owned JSON files and registered scalar TOML settings have inline forms. Journal preferences apply immediately; fix changes save for the next startup. The menu edits local files, not a connected server.

Feature switches remain in `config/skyweave/skyweave_compat-features.properties`. Village tuning uses `config/skyweave/skyweave_compat-common.toml`. Island geometry lives in `config/skyweave/skyweave_compat-generation.json`; cavity and native-carver controls live in `config/skyweave/skyweave_compat-interiors.json`. Native hydrology uses `config/skyweave/skyweave_compat-rivers.json`; adapted watersheds use upstream `config/dynamicwaters-common.toml`. Optional ocean edges use `config/skyweave/skyweave_compat-oceans.json`, and city burial uses `config/skyweave/skyweave_compat-ancient-cities.json`. Restart the game/server after changes; changed generation settings require a fresh world. The server's configuration controls multiplayer generation.

See [configuration](docs/configuration.md) for controls and limitations, [development](docs/development/README.md) for builds and verification, and [publishing](docs/publishing.md) for release instructions.
